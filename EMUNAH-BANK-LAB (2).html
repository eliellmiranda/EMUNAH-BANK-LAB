O que é o EMUNAH-BANK-LAB?

Um ambiente bancário mainframe real, usando o IBM Z Xplore hospedado na Marist College, acessado via Zowe CLI e TN3270 — focado no desenvolvimento de aplicações COBOL/JCL no contexto de um banco fictício.

💡
O lab roda em z/OS real via IBM Z Xplore (Marist College) — gratuito para estudantes. Não usa emulador local. O acesso é feito por Zowe CLI (publicação e submissão de jobs) e Vista TN3270 (Tom Brennan Software) para operação ISPF/SDSF.

Por que simular um banco?

O setor bancário é o maior empregador de profissionais mainframe no mundo. Bancos como Bradesco, Itaú, Banco do Brasil, Caixa Econômica Federal, e globalmente JPMorgan, HSBC, Deutsche Bank — todos rodam IBM z/OS 24x7. Entender o contexto bancário te diferencia no mercado.

O TK4- é uma distribuição completa do MVS 3.8j com JES2, ISPF, TSO, COBOL, Assembler, PL/I e muito mais pré-instalado.

BASH

PYTHON — gera_dados_emunah.py
import ftplib, random, datetime
from faker import Faker

fake = Faker('pt_BR')

def gera_contas(qtd=1000):
    """Gera registros de conta corrente no formato COBOL (200 bytes fixed)"""
    registros = []
    for i in range(qtd):
        conta_num  = str(i + 10000001).zfill(8)
        agencia    = str(random.randint(1, 9999)).zfill(4)
        cpf        = ''.join([str(random.randint(0,9)) for _ in range(11)])
        nome       = fake.name()[:50].ljust(50)
        saldo      = str(random.randint(0, 99999999999)).zfill(13)
        centavos   = str(random.randint(0, 99)).zfill(2)
        limite     = str(random.randint(0, 500000)).zfill(13) + '00'
        data_ab    = '20' + str(random.randint(10,24)) + \
                     str(random.randint(1,12)).zfill(2) + \
                     str(random.randint(1,28)).zfill(2)
        tipo       = random.choice(['C', 'I', 'J'])
        status     = random.choices(['A', 'A', 'A', 'B', 'E'])[0]
        qtd_trans  = str(random.randint(0, 999999)).zfill(6)
        ult_mov    = data_ab
        filler     = ' ' * 70

        rec = (conta_num + agencia + cpf + nome +
               saldo + centavos + limite +
               data_ab + tipo + status +
               qtd_trans + ult_mov + filler)

        assert len(rec) == 200, f"Erro tamanho: {len(rec)}"
        registros.append(rec)

    return registros

def envia_via_ftp(registros, dataset_name):
    """Envia dados para o mainframe via FTP"""
    with ftplib.FTP() as ftp:
        ftp.connect('127.0.0.1', 21)
        ftp.login('EMNDEV1', 'Emn@2025')
        ftp.sendcmd('site recfm=fb lrecl=200 blksize=4000')
        ftp.sendcmd('site cyl pri=5 sec=2')

        conteudo = '\n'.join(registros).encode('cp037')  # EBCDIC!

        from io import BytesIO
        ftp.storlines(f'STOR {dataset_name}', BytesIO(conteudo))
        print(ff"✓ {len(registros)} registros enviados para {dataset_name}")

if __name__ == '__main__':
    contas = gera_contas(5000)
    envia_via_ftp(contas, 'EMUNAH.CONTA.CORRENTE.LOAD')
    print("Carga inicial do EMUNAH Bank concluída!")

def submete_jcl(job_name: str, jcl_member: str):
    """Submete um membro JCL para execução no mainframe via FTP"""
    try:
        logging.info(ff"Submetendo {job_name} → {jcl_member}")
        with ftplib.FTP() as ftp:
            ftp.connect(MF_HOST, MF_PORT)
            ftp.login(MF_USER, MF_PASS)
            ftp.sendcmd('SITE FILETYPE=JES')  # modo JES submit!
            with open(ff"jcl/{jcl_member}.jcl", 'rb') as f:
                resp = ftp.storlines(ff'STOR {jcl_member}', f)
            logging.info(ff"OK — {job_name}: {resp}")
            return True
    except Exception as e:
        logging.error(ff"ERRO em {job_name}: {e}")
        return False

Fault Simulation — Aprendendo com Erros

Simulação controlada de problemas reais de mainframe bancário para treinar diagnóstico e resolução.

● Fase 6 — Fault Simulation
⚠️
Esta fase é uma das mais valiosas para o mercado. Saber diagnosticar e resolver um ABEND S0C7, um JCL error ou um VSAM RC008 te diferencia enormemente de outros candidatos.

Catálogo de Falhas Simuladas

ABEND S0C7 — Data Exception
Dado não numérico em campo numérico COBOL. O mais comum em produção bancária.
→ Simular: mover espaços para campo PIC 9 e tentar calcular. Diagnosticar via dump + offset. Resolver: INITIALIZE antes de usar variáveis.
ABEND S222 — Job cancelado pelo operador
Job cancelado manualmente (ou por timeout de SLA). Comum em batch de longa duração.
→ Simular: submeter job em loop infinito + cancelar com /C JOBNAME.CANCEL. Treinar restart/recovery do job interrompido.
VSAM RC=8 RSN=42 — Record Not Found
COBOL tenta READ VSAM KSDS por chave inexistente sem verificar file-status.
→ Simular: buscar chave de conta deletada. Treinar validação de WS-STATUS-VSAM após cada I/O VSAM.
JCL Error — JCLERR, NOT CAT
Dataset referenciado no JCL não existe no catálogo. Job termina antes de executar.
→ Simular: referenciar dataset com nome errado. Treinar leitura do JCLERR no SYSOUT e correção do JCL.
ABEND S0C4 — Storage Protection Exception
Programa tenta acessar área de memória não autorizada. Causa: ponteiro errado, tabela fora de limites.
→ Simular: subscript COBOL além do tamanho da tabela. Diagnosticar com CEEDUMP. Resolver: PERFORM VARYING com UNTIL correto.
DFSORT RC=16 — Sort terminou com erro
Sort VSAM com SYSIN incorreto ou arquivo de entrada vazio.
→ Simular: passar arquivo vazio ao DFSORT. Treinar verificação COND= no JCL e tratamento de arquivo vazio.
MAXCC > 0 — Condition Code inesperado
Step anterior retornou CC=8 e step seguinte não testou com COND=.
→ Simular: remover COND= de steps dependentes. Treinar cascata de erros e importância do COND=.

FAULT_CATALOG = {
    'S0C7_DATA': {
        'jcl': 'FAULT_S0C7.jcl',
        'desc': 'Data Exception — campo numérico com espaços',
        'prob': 0.10  # 10% de chance por ciclo
    },
    'VSAM_RC8': {
        'jcl': 'FAULT_VSAM.jcl',
        'desc': 'VSAM record not found',
        'prob': 0.15
    },
    'JCL_ERR': {
        'jcl': 'FAULT_JCL.jcl',
        'desc': 'Dataset inválido no JCL',
        'prob': 0.08
    },
    'SORT_EMPTY': {
        'jcl': 'FAULT_SORT.jcl',
        'desc': 'Arquivo vazio enviado ao DFSORT',
        'prob': 0.05
    }
}

def inject_random_fault():
    """Injeta uma falha aleatória baseada nas probabilidades configuradas"""
    for fault_name, config in FAULT_CATALOG.items():
        if random.random() < config['prob']:
            logging.warning(ff"🔥 FALHA INJETADA: {fault_name} — {config['desc']}")
            # Submete JCL que vai causar o erro proposital
            submete_jcl_fault(config['jcl'])
            return fault_name
    return None

Procedimentos de Diagnóstico e Correção

Manual operacional para consulta rápida quando ocorrer um erro. Para cada incidente: sintoma → causa → diagnóstico → ação → evidências.

RB1

Arquivo de Entrada Ausente

Sintoma: EBJLOAD falha, cadeia bloqueada

▼
Causa provávelDataset ausente, nome incorreto, falha no upload, erro de catálogo
Diagnósticozowe zos-files list data-set "Z77948.EMUNAH.ARQ.ENTRADA.SEQ" — verifica existência
Ação corretivaReenviar o arquivo de entrada corrigindo nome/destino. Repetir upload. Reexecutar EBJLOAD.
EvidênciasSpool do job, lista de datasets, horário do reenvio
RB2

Layout Inválido no Arquivo de Entrada

Sintoma: EBJVALD gera muitos rejeitos ou RC elevado

▼
Causa provávelTamanho incorreto, tipo inválido, valor errado, data fora do padrão, conta inexistente
DiagnósticoRelatório de validação no spool + análise de ARQ.REJEITO.SEQ + comparação com copybook CPLCT001
Ação corretivaCorrigir arquivo de entrada ou ajustar layout. Reenviar. Reexecutar EBJVALD.
EvidênciasRegistros rejeitados, motivo de rejeição, versão do layout utilizado
RB3

Conta Inexistente ou Inválida

Sintoma: rejeição de lançamentos na validação ou na aplicação

▼
Causa provávelConta ausente em ARQ.CONTA.KSDS, carga inicial incompleta, chave incorreta
DiagnósticoFile Manager ou IDCAMS PRINT → consulta ao KSDS de contas. Verificar chave agência+conta.
Ação corretivaCorrigir massa de entrada OU recarregar o cadastro da conta. Reprocessar via EBJREPR.
EvidênciasSpool de validação/aplicação, prova de ausência da conta, massa corrigida
RB4

Falha na Aplicação de Lançamentos

Sintoma: EBJPOST falha — RC elevado ou ABEND

▼
Causa provávelErro de lógica, conta bloqueada, saldo insuficiente, falha na gravação VSAM
DiagnósticoSpool do EBJPOST + SYSABEND dump (se ABEND) + verificação do CONTA.KSDS via File Manager
Ação corretivaCorrigir programa → recompilar → reenviar. Reprocessar apenas com ambiente consistente.
EvidênciasSpool, RC, registros afetados, impacto parcial ou total
RB5

Falha de Conciliação

Sintoma: EBJCONC falha, fechamento bloqueado

▼
Causa provávelDivergência totais entrada/saída, saldo incorreto, extrato com erro
DiagnósticoComparar: QTD entrada = QTD válidos + QTD rejeitos. Verificar saldo consolidado.
Ação corretivaLocalizar divergência → corrigir causa → reexecutar etapa necessária. EBJEOD nunca roda com divergência.
EvidênciasRelatório de conciliação, totais esperados vs. obtidos, logs dos jobs
RB6

Job em HOLD ou Não Executado

Sintoma: job parado no spool, não inicia

▼
Causa provávelStatus HOLD, dependência anterior não atendida, predecessor com falha
DiagnósticoSDSF → ST → status do job. Zowe Explorer para visão rápida. Verificar grade batch.
Ação corretivaLiberar job, reenviar ou corrigir dependência anterior. Reprocessar a partir do job afetado.
EvidênciasStatus do job, tela do SDSF, horários de parada e liberação
RB7

Reprocessamento de Rejeitos

Registros corrigidos aguardando reaplicação

▼
Causa típicaErro anterior identificado e corrigido — registros prontos para reaplicação
DiagnósticoVerificar ARQ.REJEITO.SEQ + causa original + consistência do arquivo corrigido
Ação corretivaPreparar arquivo corrigido → subir para mainframe → executar EBJREPR → validar impacto em saldo/extrato
EvidênciasRejeitos originais, versão corrigida, spool do EBJREPR
📋
Regra geral de evidências: Sempre guardar — nome do job, horário, RC, spool principal, datasets afetados, ação executada e decisão sobre reprocessamento.

🔴
Os três membros executam EXEC IGYWCL com os mesmos parâmetros. A IGYWCL já faz compile + link em uma só chamada. Ter três membros idênticos gera confusão operacional e não agrega nada ao aprendizado.

O que cada um deveria ser:

MembroDeve fazerPrograma

EBCOMPSó compilação, gera objeto em temp datasetIGYCRCTL
EBLINKSó link-edição, lê objeto gerado pelo EBCOMPIEWBLINK

INC-02 EBPOST01 lê direto da ENTRADA.SEQ, deveria ler da LANCTO.ESDS Fluxo batch ▼

O fluxo correto num ambiente bancário real é:

           MOVE LCT-NSEQ    TO WS-CHAVE-LANCTO-SEQ

               INVALID KEY

                   MOVE 'D' TO WS-STATUS-LANCTO
                   ADD 1 TO WS-DUPLICADOS
                   *> ja existe! nao reprocessa
           END-READ.

       2200-REAPLICA.

Control-M é o scheduler batch mais usado em bancos brasileiros. Você não vai usar o produto real (licença cara), mas vai aprender os conceitos e simular o comportamento.

⏰
BMC Control-M
Workload Automation · Job Scheduling · Dependency Engine
ℹ️
O que é: Control-M é um schedulador de jobs batch. Em vez de submeter JCL manualmente, o Control-M sabe: quem depende de quem, em que hora, em que dia do mês, com que condições. No Bradesco, Itaú, Caixa — toda a cadeia batch roda pelo Control-M ou pelo CA7 (concorrente).

from datetime import datetime

logging.basicConfig(

# Mapa de dependências — simula o flow do Control-M
FLOW = {
    "EBJLOAD": {
        "predecessors": [],               # sem predecessor
        "jcl_member": "EBJLOAD",
        "condition_out": "LOAD-OK",
        "max_rc": 0
    },
    "EBJVALD": {
        "predecessors": ["LOAD-OK"],
        "jcl_member": "EBJVALD",
        "condition_out": "VALD-OK",
        "max_rc": 4
    },
    "EBJPOST": {
        "predecessors": ["VALD-OK"],
        "jcl_member": "EBJPOST",
        "condition_out": "POST-OK",
        "max_rc": 4
    },
    "EBJSALD": {
        "predecessors": ["POST-OK"],
        "jcl_member": "EBJSALD",
        "condition_out": "SALD-OK",
        "max_rc": 4
    },
    "EBJEXTR": {
        "predecessors": ["SALD-OK"],
        "jcl_member": "EBJEXTR",
        "condition_out": "EXTR-OK",
        "max_rc": 0
    },
    "EBJCONC": {
        "predecessors": ["EXTR-OK"],
        "jcl_member": "EBJCONC",
        "condition_out": "CONC-OK",
        "max_rc": 0
    },
    "EBJEOD": {
        "predecessors": ["CONC-OK"],
        "jcl_member": "EBJEOD",
        "condition_out": "EOD-OK",
        "max_rc": 0
    },
}

conditions_ativas = set()  # conditions satisfeitas
HLQ = "Z77948.EMUNAH.DEV.JCL"

def submete_e_aguarda(job_name, member):
    """Submete JCL via Zowe e aguarda completion"""
    logging.info(f"SUBMIT {job_name}")
    result = subprocess.run(
        ["zowe", "zos-jobs", "submit", "data-set", f"{HLQ}({member})"],
        capture_output=True, text=True
    )
    # Extrai jobid da saida do Zowe
    jobid = None
    for line in result.stdout.splitlines():
        if 'jobid' in line.lower() or 'JOB' in line:
            jobid = line.split()[-1].strip()
            break
    if not jobid:
        logging.error(f"Nao foi possivel obter JOBID para {job_name}")
        return 99
    # Aguarda completion
    for _ in range(30):  # max 150s
        time.sleep(5)
        st = subprocess.run(
            ["zowe", "zos-jobs", "view", "job-status-by-jobid", jobid],
            capture_output=True, text=True
        )
        if "OUTPUT" in st.stdout or "CC " in st.stdout:
            rc_line = [l for l in st.stdout.splitlines() if "CC " in l]
            rc = int(rc_line[-1].split("CC ")[-1].strip()[:4]) if rc_line else 0
            logging.info(f"{job_name} ({jobid}) RC={rc}")
            return rc
    logging.error(f"Timeout aguardando {job_name}")
    return 99

def roda_flow():
    """Executa o flow do dia simulando o Control-M"""
    logging.info("=== EMUNAH CTM-SIM — INICIO DO DIA ===")
    for job, cfg in FLOW.items():
        # Verifica predecessores
        pendentes = [p for p in cfg["predecessors"] if p not in conditions_ativas]
        if pendentes:
            logging.warning(f"[HOLD] {job} — aguardando conditions: {pendentes}")
            continue
        rc = submete_e_aguarda(job, cfg["jcl_member"])
        if rc <= cfg["max_rc"]:
            conditions_ativas.add(cfg["condition_out"])
            logging.info(f"[OK] Condition {cfg['condition_out']} adicionada")
        else:
            logging.error(f"[FAIL] {job} RC={rc} — Flow BLOQUEADO")
            break
    logging.info("=== FLOW CONCLUIDO ===")

if __name__ == "__main__":
    roda_flow()

Script de Promoção DEV → HML (simula Endevor Promote)

PowerShell — scripts/promote_dev_hml.ps1
# promote_dev_hml.ps1 — Promove elemento de DEV para HML
# Simula o PROMOTE do Endevor/ChangeMan
param(
  [Parameter(Mandatory=$true)]
  [string]$Programa,     # Ex: EBPOST01
  [string]$Tipo = "COBOL" # COBOL, JCL, COPY
)

$HLQ_DEV = "Z77948.EMUNAH.DEV"
$HLQ_HML = "Z77948.EMUNAH.HML"
$DATE    = Get-Date -Format "yyyyMMdd-HHmmss"

Write-Host "[PROMOTE] $Tipo($Programa) DEV -> HML"
Write-Host "[PROMOTE] Data: $DATE"

# 1. Verifica existencia no DEV
$check = zowe zos-files list members "$HLQ_DEV.$Tipo" 2>&1
if ($check -notmatch $Programa) {
    Write-Error "[PROMOTE] ERRO: $Programa nao encontrado em $HLQ_DEV.$Tipo"
    exit 8
}

# 2. Copia membro DEV para HML via REXX no host
$rexx = @"
/* REXX - Copia membro DEV para HML */
CALL OUTTRAP 'LINHAS.'
'ISPEXEC LMINIT DATAID(DEVIN) DATASET(''$HLQ_DEV.$Tipo'')'
'ISPEXEC LMINIT DATAID(HMLOUT) DATASET(''$HLQ_HML.$Tipo'')'
'ISPEXEC LMCOPY FROMID(DEVIN) FROMMEM($Programa) '||,
         'TODATAID(HMLOUT) TOMEM($Programa) REPLACE'
'ISPEXEC LMFREE DATAID(DEVIN)'
'ISPEXEC LMFREE DATAID(HMLOUT)'
SAY 'PROMOTE OK: $Programa DEV->HML'
Return 0
"@

$rexx | Out-File ".\rexx\temp\PROMOTE.rex" -Encoding ASCII
zowe zos-files upload file-to-data-set ".\rexx\temp\PROMOTE.rex" "Z77948.EMUNAH.DEV.REXX(PROMOTE)"

Write-Host "[PROMOTE] Registrando no change log..."
Add-Content ".\docs\change-log.md" "| $DATE | PROMOTE | $Tipo | $Programa | DEV->HML | $(git log -1 --pretty='%s') |"

Write-Host "[PROMOTE] Concluido. Lembre de recompilar em HML!"

Como ler o dump gerado (sem Fault Analyzer)

DUMP READING — Guia de diagnóstico manual
Quando o job terminar com ABEND S0C7, no spool SYSABEND:

1. Procure a linha: "COMPLETION CODE  SYSTEM=0C7"
   COMPLETION CODE  SYSTEM=0C7  USER=0000

2. Ache o PSW (Program Status Word) e o offset:
   ABEND S0C7  PSW AT ABEND 00E00000 8001AB3C
               └── 8001AB3C = endereço da instrução que falhou

3. No SYSPRINT do compilador (com MAP), localize o offset:
   Subtraia o endereço do início do programa do endereço do ABEND
   Essa diferença é o OFFSET dentro do programa compilado

4. No mapa de compilação (SYSPRINT com LIST,MAP), encontre
   qual paragrafo/instrução corresponde a esse offset

5. Regra prática: procure no dump por registros GR0-GR15
   Em S0C7, o registrador que aponta para o dado inválido
   vai estar numa área com caracteres não numéricos
