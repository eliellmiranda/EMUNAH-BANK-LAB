00 // VISÃO GERAL

O que é o EMUNAH-BANK-LAB?

Um ambiente mainframe completo, rodando localmente (ou em VM/cloud), que simula o dia a dia de um banco usando tecnologias reais de mainframe IBM.

💡
O lab usa o emulador Hercules com o sistema operacional MVS 3.8j (TK4-), que é gratuito e open source. Para ambientes mais próximos do mercado atual, usamos o z/OS 2.5 Developer Edition (gratuito via IBM Developer Trials ou zXplore). Ambos rodam TN3270, JCL, COBOL, VSAM e muito mais.

Por que simular um banco?

O setor bancário é o maior empregador de profissionais mainframe no mundo. Bancos como Bradesco, Itaú, Banco do Brasil, Caixa Econômica Federal, e globalmente JPMorgan, HSBC, Deutsche Bank — todos rodam IBM z/OS 24x7. Entender o contexto bancário te diferencia no mercado.

Instalar o Hercules Emulator

Emulador open source do hardware IBM System/370, 390, z/Series

▼
ℹ️
Hercules roda em Linux, Windows e macOS. A versão recomendada é o Hercules 4.x (SDL-Hercules) — mais estável e atualizado.

Linux (Ubuntu/Debian) — recomendado

BASH 
# Atualiza e instala dependências
sudo apt update && sudo apt upgrade -y
sudo apt install -y build-essential git cmake \
  libz-dev zlib1g-dev libbz2-dev \
  libjansson-dev libregina0-dev

# Clona o SDL-Hercules (versão mais mantida)
git clone https://github.com/SDL-Hercules-390/hyperion.git
cd hyperion

# Compila
./autogen.sh
./configure --enable-optimization
make -j$(nproc)
sudo make install

# Verifica instalação
hercules --version

Windows — alternativa simples

💡
No Windows, use o instalador pré-compilado em http://hercules-390.eu → Download → Windows Binary. Ou use WSL2 + Ubuntu e siga o passo Linux acima.

Docker — para quem quer simplicidade máxima

BASH 
# Pull da imagem pré-configurada com TK4-
docker pull rattydave/docker-ubuntu-hercules-mvs:latest

# Roda o container
docker run -d \
  --name emunah-mainframe \
  -p 3270:3270 \
  -p 8038:8038 \
  -v ~/emunah-lab:/home/hercules/custom \
  rattydave/docker-ubuntu-hercules-mvs

# Acessa via TN3270 em localhost:3270
1.2

Instalar TK4- (MVS 3.8j)

O sistema operacional mainframe gratuito mais completo disponível

▼

O TK4- é uma distribuição completa do MVS 3.8j com JES2, ISPF, TSO, COBOL, Assembler, PL/I e muito mais pré-instalado.

BASH 
# Cria o diretório do lab
mkdir -p ~/emunah-bank-lab && cd ~/emunah-bank-lab

# Download do TK4- (versão atual: update 09)
wget http://wotho.ethz.ch/tk4-/tk4-_v1.00_current.zip

# Extrai
unzip tk4-_v1.00_current.zip
cd tk4-

# Estrutura de diretórios criada:
# conf/      — arquivos de configuração Hercules
# dasd/      — discos virtuais (volumes VSAM, SYS1, etc)
# hercules/  — binário do emulador
# jcl/       — jobs de exemplo
# prt/       — impressora virtual (SYSOUT)
# pch/       — card punch virtual

# Starta o sistema
./mvs
💡
Após o start, aguarde o MVS inicializar completamente. Você verá a mensagem HASP426 NOTIFY -- SYSLOG ACTIVE quando estiver pronto. Leva cerca de 2-3 minutos.

Verificando a inicialização

MVS CONSOLE 
/* Na console do Hercules, digitar: */
/$D A,ALL    ← verifica initiators ativos
/D J,ALL     ← verifica jobs em execução
/D T         ← verifica hora do sistema

Primeiro Login — TSO/ISPF

Navegando no ambiente mainframe como desenvolvedor

▼
💡
No TK4-, o usuário padrão é HERC01 e a senha é CUL8TR (ou HERC02/CUL8TR para segundo usuário). Depois vamos criar usuários específicos para o EMUNAH.
TSO COMMANDS
/* Fluxo de login */
1. Conecta TN3270 → aparece tela VTAM/MVS
2. Digita: TSO     ← acessa Time Sharing Option
3. USERID: HERC01
4. PASSWORD: CUL8TR
5. READY prompt → digita: ISPF  ← entra no ambiente ISPF

/* Menu principal ISPF */
OPTION ===>
  0  Settings
  1  View
  2  Edit         ← editar datasets/programas
  3  Utilities    ← gerenciar datasets
  4  Foreground   ← compilar COBOL
  5  Batch        ← submeter JCL
  6  Command
  7  Dialog Test
  M  More...
  X  Exit

Comandos TSO mais usados no dia a dia

TSO / ISPF COMMANDS
/* Navegar datasets */
ISPF 3.4    ← Dataset list (DSLIST)
ISPF 2      ← Edit um dataset diretamente

/* No prompt TSO (fora do ISPF) */
LISTDS 'EMUNAH.CONTA.CORRENTE' MEMBERS  ← lista datasets
ALLOCATE FILE(MEUFILE) DATASET('EMUNAH.CONTA.CORRENTE') SHR
FREE FILE(MEUFILE)

/* Submeter JCL direto do TSO */
SUBMIT 'EMUNAH.JCL(EMNJOB01)'

/* Ver output de job */
SDSF (ST) → lista jobs submetidos → / ao lado do job → ? para ver outputs

MF_HOST = '127.0.0.1'
MF_PORT = 21
MF_USER = 'EMNOPER'
MF_PASS = 'Emn@2025'

def submete_jcl(job_name: str, jcl_member: str):
    """Submete um membro JCL para execução no mainframe via FTP"""
    try:
        logging.info(ff"Submetendo {job_name} → {jcl_member}")
        with ftplib.FTP() as ftp:
            ftp.connect(MF_HOST, MF_PORT)
            ftp.login(MF_USER, MF_PASS)
            ftp.sendcmd('SITE FILETYPE=JES')  # modo JES submit!
            with open(ff"jcl/{jcl_member}.jcl", 'rb') as f:
                resp = ftp.storlines(ff'STOR {jcl_member}', f)
            logging.info(ff"OK — {job_name}: {resp}")
            return True
    except Exception as e:
        logging.error(ff"ERRO em {job_name}: {e}")
        return False

# ─── SCHEDULE BANCÁRIO ───────────────────────────────
schedule.every().day.at("00:00").do(submete_jcl, "FECHAMENTO",   "EMNJOB01")
schedule.every().day.at("00:30").do(submete_jcl, "EXTRATOS",     "EMNJOB02")
schedule.every().day.at("01:00").do(submete_jcl, "DEBITO-AUTO",  "EMNJOB03")
schedule.every().day.at("02:00").do(submete_jcl, "POUPANCA",     "EMNJOB04")

schedule.every().day.at("04:00").do(submete_jcl, "RELATORIOS",   "EMNJOB06")
schedule.every().day.at("05:00").do(submete_jcl, "BACKUP",       "EMNJOB07")

Fault Simulation — Aprendendo com Erros

Simulação controlada de problemas reais de mainframe bancário para treinar diagnóstico e resolução.

● Fase 6 — Fault Simulation
⚠️
Esta fase é uma das mais valiosas para o mercado. Saber diagnosticar e resolver um ABEND S0C7, um JCL error ou um VSAM RC008 te diferencia enormemente de outros candidatos.

Catálogo de Falhas Simuladas

ABEND S0C7 — Data Exception
Dado não numérico em campo numérico COBOL. O mais comum em produção bancária.
→ Simular: mover espaços para campo PIC 9 e tentar calcular. Diagnosticar via dump + offset. Resolver: INITIALIZE antes de usar variáveis.
ABEND S222 — Job cancelado pelo operador
Job cancelado manualmente (ou por timeout de SLA). Comum em batch de longa duração.
→ Simular: submeter job em loop infinito + cancelar com /C JOBNAME.CANCEL. Treinar restart/recovery do job interrompido.
VSAM RC=8 RSN=42 — Record Not Found
COBOL tenta READ VSAM KSDS por chave inexistente sem verificar file-status.
→ Simular: buscar chave de conta deletada. Treinar validação de WS-STATUS-VSAM após cada I/O VSAM.
JCL Error — JCLERR, NOT CAT
Dataset referenciado no JCL não existe no catálogo. Job termina antes de executar.
→ Simular: referenciar dataset com nome errado. Treinar leitura do JCLERR no SYSOUT e correção do JCL.
ABEND S0C4 — Storage Protection Exception
Programa tenta acessar área de memória não autorizada. Causa: ponteiro errado, tabela fora de limites.
→ Simular: subscript COBOL além do tamanho da tabela. Diagnosticar com CEEDUMP. Resolver: PERFORM VARYING com UNTIL correto.
DFSORT RC=16 — Sort terminou com erro
Sort VSAM com SYSIN incorreto ou arquivo de entrada vazio.
→ Simular: passar arquivo vazio ao DFSORT. Treinar verificação COND= no JCL e tratamento de arquivo vazio.
MAXCC > 0 — Condition Code inesperado
Step anterior retornou CC=8 e step seguinte não testou com COND=.
→ Simular: remover COND= de steps dependentes. Treinar cascata de erros e importância do COND=.

PYTHON — fault_injector.py
import random, time, ftplib, logging

FAULT_CATALOG = {
    'S0C7_DATA': {
        'jcl': 'FAULT_S0C7.jcl',
        'desc': 'Data Exception — campo numérico com espaços',
        'prob': 0.10  # 10% de chance por ciclo
    },
    'VSAM_RC8': {
        'jcl': 'FAULT_VSAM.jcl',
        'desc': 'VSAM record not found',
        'prob': 0.15
    },
    'JCL_ERR': {
        'jcl': 'FAULT_JCL.jcl',
        'desc': 'Dataset inválido no JCL',
        'prob': 0.08
    },
    'SORT_EMPTY': {
        'jcl': 'FAULT_SORT.jcl',
        'desc': 'Arquivo vazio enviado ao DFSORT',
        'prob': 0.05
    }
}

def inject_random_fault():
    """Injeta uma falha aleatória baseada nas probabilidades configuradas"""
    for fault_name, config in FAULT_CATALOG.items():
        if random.random() < config['prob']:
            logging.warning(ff"🔥 FALHA INJETADA: {fault_name} — {config['desc']}")
            # Submete JCL que vai causar o erro proposital
            submete_jcl_fault(config['jcl'])
            return fault_name
    return None

# Roda a cada 6 horas junto com o ciclo de batch
while True:
    fault = inject_random_fault()
    if fault:
        logging.info(ff"Falha ativa para diagnóstico: {fault}")
    time.sleep(21600)  # 6 horas
