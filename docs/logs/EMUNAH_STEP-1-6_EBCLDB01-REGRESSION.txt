 ISSUES ENCOUNTERED AND RESOLVED
 -------
 Issue: DSNE102I YOU ARE NOT AUTHORIZED TO USE DB2 SUBSYSTEM DBD1
   Root cause: RACF DSNR class profiles DBD1.BATCH and DBD1.TSO
               existed but ELIEL and IBMUSER had no PERMIT entries.
               DBD1.TSO profile was missing entirely (lost in backup
               recovery). SETROPTS CLASSACT(DSNR) was active so all
               access was blocked.
   Fix applied (as IBMUSER):
     RDEFINE DSNR DBD1.TSO UACC(NONE)
     PERMIT DBD1.BATCH CLASS(DSNR) ID(ELIEL)   ACCESS(READ)
     PERMIT DBD1.BATCH CLASS(DSNR) ID(IBMUSER) ACCESS(READ)
     PERMIT DBD1.TSO   CLASS(DSNR) ID(ELIEL)   ACCESS(READ)
     PERMIT DBD1.TSO   CLASS(DSNR) ID(IBMUSER) ACCESS(READ)
     SETROPTS RACLIST(DSNR) REFRESH

 Additional lesson:
   GRANT SQL statement cannot be issued at the DSN prompt directly.
   Must be run via RUN PROGRAM(DSNTIAD) or SPUFI.
   ALLOC FI(STEPLIB) is restricted in TSO interactive sessions —
   use batch JCL with STEPLIB DD for DB2 load library access.
