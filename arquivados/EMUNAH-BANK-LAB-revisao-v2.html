9 Problemas que vão fazer o lab quebrar

Esses bugs impedem a execução correta da cadeia batch. Devem ser corrigidos antes de qualquer incremento.

● Bloqueadores — corrigir imediatamente
BUG-01 EBBUILD = EBCOMP = EBLINK — os três JCLs são idênticos jcl/compile/ ▼
🔴
Os três membros executam EXEC IGYWCL com os mesmos parâmetros. A IGYWCL já faz compile + link em uma só chamada. Ter três membros idênticos gera confusão operacional e não agrega nada ao aprendizado.

O que cada um deveria ser:

MembroDeve fazerPrograma
EBBUILDCompile + Link (all-in-one) — CORRETOIGYWCL
EBCOMPSó compilação, gera objeto em temp datasetIGYCRCTL
EBLINKSó link-edição, lê objeto gerado pelo EBCOMPIEWBLINK

Correção — EBCOMP (só compile):

JCL — EBCOMP corrigido
//* EBCOMP — Apenas compilacao do fonte COBOL
//EBCOMP   JOB ,'EMUNAH COMP',CLASS=A,MSGCLASS=X,MSGLEVEL=(1,1)
//COMPILE  EXEC PGM=IGYCRCTL,PARM='OBJECT,LIST,MAP,APOST,RENT'
//SYSPRINT DD  SYSOUT=*
//SYSLIB   DD  DSN=Z77948.EMUNAH.DEV.COPY,DISP=SHR
//SYSIN    DD  DSN=Z77948.EMUNAH.DEV.COBOL(&PGMNAME),DISP=SHR
//SYSLIN   DD  DSN=&&OBJ,DISP=(,PASS),UNIT=SYSDA,
//             SPACE=(TRK,(1,1)),DCB=(RECFM=FB,LRECL=80,BLKSIZE=3200)
//SYSUT1   DD  UNIT=SYSDA,SPACE=(CYL,(1,1))
//SYSUT2   DD  UNIT=SYSDA,SPACE=(CYL,(1,1))
//SYSUT3   DD  UNIT=SYSDA,SPACE=(CYL,(1,1))
//SYSUT4   DD  UNIT=SYSDA,SPACE=(CYL,(1,1))
//SYSUT5   DD  UNIT=SYSDA,SPACE=(CYL,(1,1))
//SYSOUT   DD  SYSOUT=*
💡
O EBBUILD com IGYWCL é o mais usado no dia a dia. EBCOMP e EBLINK separados servem para treinar o processo de compilação em dois estágios, útil quando você precisar especificar opções de link avançadas.

BUG-04 EBJPOST usa DD ENTRADA mas EBPOST01 espera MOVTIN jcl/batch/EBJPOST.jcl × cobol/batch/EBPOST01.cbl ▼

  //STEP1    EXEC PGM=EBPOST01
  //STEPLIB  DD DSN=Z77948.EMUNAH.DEV.LOADLIB,DISP=SHR

BUG-08 EBCLLOAD abre CLIENTE-KSDS com I-O mas deveria abrir com OUTPUT na primeira carga cobol/batch/EBCLLOAD.cbl ▼
🔴
Com OPEN I-O num VSAM KSDS vazio, se o arquivo não foi inicializado corretamente, você pode receber um VSAM RC=120 RSN=10. Para a carga inicial, use OPEN OUTPUT. Para recarga (com I-O), certifique-se que o VSAM já foi alocado e tem componentes válidos.
-      OPEN I-O   CLIENTE-KSDS
-      OPEN I-O   CONTA-KSDS
+      OPEN OUTPUT CLIENTE-KSDS
+      OPEN OUTPUT CONTA-KSDS
*      Para reprocessamento (dados já existem), volte para I-O
*      e adicione INVALID KEY tratamento na gravação
⚠️
Com OPEN OUTPUT, o VSAM é iniciado do zero. Use isso na carga inicial. Nas recargas subsequentes, use I-O com tratamento de INVALID KEY para duplicidade.
BUG-09 Typo no mapa de datasets: EMUNHA.ARQ.LANCTO.ESDS docs/04-mapa-datasets.md ▼
🔴
O mapa lista EMUNHA.ARQ.LANCTO.ESDS (EMUNHA com H antes do A) em vez de EMUNAH.ARQ.LANCTO.ESDS. Se alguém criar o dataset pelo mapa errado, nenhum programa vai achar o arquivo.

5 Pontos que criam confusão mas não quebram tudo

Problemas de nomenclatura, design e documentação que vão gerar dúvida na operação.

INC-01 EBJCLLD e EBJLOAD fazem a mesma coisa — um precisa ir jcl/batch/ ▼

EBJCLLD (carga inicial de clientes/contas do seed) e EBJLOAD (preparação do arquivo do dia) são dois jobs diferentes que acabaram colidindo no nome. A distinção certa é:

JobFinalidade corretaQuando rodar
EBJCLLDCarga inicial (seed → KSDS). Roda 1x na vida do lab.Setup inicial
EBJLOADVerificação/preparação do arquivo de entrada do dia.Todo dia na cadeia
💡
Renomeie EBJCLLD para EBSETUP ou EBSEED para deixar claro que é one-time setup. Isso elimina a ambiguidade.
INC-02 EBPOST01 lê direto da ENTRADA.SEQ, deveria ler da LANCTO.ESDS Fluxo batch ▼

O fluxo correto num ambiente bancário real é:

ENTRADA.SEQ (bruto)
    │
    ▼
EBJVALD → EBVALI01
    │
    ├──► LANCTO.ESDS  (registros VÁLIDOS — entrada para EBJPOST)
    └──► REJEITO.SEQ  (registros inválidos — diagnóstico)
         │
         ▼
    EBJPOST → EBPOST01
         │ lê de LANCTO.ESDS (não da ENTRADA.SEQ bruta!)
         ▼
    CONTA.KSDS atualizado

O EBPOST01 atual lê MOVTIN que aponta para... nada de útil no JCL (BUG-04). Corrija o JCL para apontar para LANCTO.ESDS como entrada do EBPOST01.

INC-03 EBJEOD ainda é IEFBR14 placeholder — não faz nada real jcl/batch/EBJEOD.jcl ▼

O fechamento diário (EOD) deve, minimamente:

  • Atualizar um dataset de controle com a data/hora do fechamento
  • Registrar no arquivo de auditoria que o dia foi encerrado com sucesso
  • Gerar um backup do estado final dos arquivos VSAM (via IDCAMS REPRO)

INC-04 Nenhum JCL usa COND= para dependência — cadeia não para em caso de erro Todos os JCLs batch ▼

Em produção real, jobs dependentes verificam o RC do predecessor. Sem COND=, mesmo que o EBJVALD termine com RC=8, o EBJPOST vai rodar. Isso gera dados inconsistentes.

JCL — adicionando COND= correto
//EBJPOST  JOB ,'EMUNAH POST',CLASS=A,MSGCLASS=X,MSGLEVEL=(1,1)
//STEP1    EXEC PGM=EBPOST01,COND=(4,LT)
//* COND=(4,LT) significa: se RC anterior < 4, execute
//* Se o EBJVALD retornar RC=8 (erro), o EBJPOST para
//* RC=0 = perfeito, RC=4 = aviso (continua), RC=8+ = erro
INC-05 EBBUILD hardcoded para EBCLLOAD — cada programa precisa de seu build jcl/compile/EBBUILD.jcl ▼

Você tem 6+ programas COBOL. Criar um EBBUILD separado para cada é trabalhoso. A solução de mercado é um job genérico com PARM ou um script Zowe que parameteriza o build.

SCRIPT — build_programa.ps1 (PowerShell local)
# build_programa.ps1 — Compila qualquer programa do lab
param(
  [Parameter(Mandatory=$true)]
  [string]$Programa  # Ex: EBPOST01
)

$jcl = @"
//EBBUILD  JOB ,'EMUNAH BUILD',CLASS=A,MSGCLASS=X,MSGLEVEL=(1,1)
//CL       EXEC IGYWCL
//COBOL.SYSIN   DD DSN=Z77948.EMUNAH.DEV.COBOL($Programa),DISP=SHR
//COBOL.SYSLIB  DD DSN=Z77948.EMUNAH.DEV.COPY,DISP=SHR
//LKED.SYSLMOD  DD DSN=Z77948.EMUNAH.DEV.LOADLIB($Programa),DISP=SHR
//LKED.SYSPRINT DD SYSOUT=*
//*
"@

# Grava JCL temporário e submete via Zowe
$jcl | Out-File -FilePath ".\jcl\temp\BUILD_$Programa.jcl" -Encoding ASCII
zowe zos-files upload file-to-data-set ".\jcl\temp\BUILD_$Programa.jcl" "Z77948.EMUNAH.DEV.JCL(EBBUILD)"
zowe zos-jobs submit data-set "Z77948.EMUNAH.DEV.JCL(EBBUILD)"
Write-Host "Build de $Programa submetido."
💡
Uso: .\build_programa.ps1 -Programa EBPOST01. Isso cria o JCL dinamicamente para qualquer programa, sem precisar editar o membro no host.

PRECHECK em REXX — Verificação pré-batch

Verifica existência de datasets e integridade antes de rodar a cadeia

▼
REXX — EMUNAH.DEV.REXX(PRECHECK)
/* REXX ─────────────────────────────────────── */
/* PRECHECK — Verifica ambiente pre-batch       */
/* RC=0 ambiente OK / RC=8 falha critica        */
/* ──────────────────────────────────────────── */

SAY '=== EMUNAH BANK — PRE-CHECK ==='
WS_RC = 0

/* Lista de datasets obrigatorios */
DSN.1 = 'Z77948.EMUNAH.ARQ.ENTRADA.SEQ'
DSN.2 = 'Z77948.EMUNAH.ARQ.CLIENTE.KSDS'
DSN.3 = 'Z77948.EMUNAH.ARQ.CONTA.KSDS'
DSN.4 = 'Z77948.EMUNAH.ARQ.LANCTO.ESDS'
DSN.5 = 'Z77948.EMUNAH.DEV.LOADLIB'
DSN.0 = 5

Do i = 1 To DSN.0
  x = LISTDSI(DSN.i)
  If x = 0 Then
    SAY '[OK]  ' DSN.i
  Else Do
    SAY '[ERRO]' DSN.i '- AUSENTE OU INACESSIVEL'
    WS_RC = 8
  End
End

If WS_RC = 0 Then
  SAY '>>> PRE-CHECK OK — Cadeia pode iniciar'
Else
  SAY '>>> PRE-CHECK FALHOU — Corrija antes de rodar a cadeia'

Return WS_RC

# build.ps1 — Build parametrico EMUNAH-BANK-LAB
param([string]$Pgm = "EBCLLOAD", [switch]$Run)

$hq  = "Z77948.EMUNAH"
$jcl = @"
//EBBUILD  JOB ,'EB $Pgm',CLASS=A,MSGCLASS=X,MSGLEVEL=(1,1)

Upgrade do CPAUD001 — Auditoria estruturada em todos os programas

Substituir STRING livre por copybook CPAUD001 padronizado

▼

Você já tem o copybook CPAUD001 definido mas nenhum programa o usa ainda. Os programas usam PIC X(120) com STRING livre. O upgrade é:

COBOL — padrão de auditoria estruturada
      * No FD do arquivo de auditoria:
       FD  AUDIT-OUT
           RECORD CONTAINS 128 CHARACTERS
           RECORDING MODE IS F.
       01  AUDIT-REG.
           COPY CPAUD001.

      * Na WORKING-STORAGE:
       01  WS-AUDIT-WORK.
           COPY CPAUD001.

      * Na gravação estruturada:
       8800-GRAVA-AUDIT.
           MOVE 'ERRO'          TO AU-TIPO-EVENTO OF WS-AUDIT-WORK
           MOVE 'EBPOST01'    TO AU-PROGRAMA     OF WS-AUDIT-WORK
           MOVE WS-DATA-HOJE  TO AU-DATA-EVENTO  OF WS-AUDIT-WORK
           MOVE WS-HORA-ATUAL TO AU-HORA-EVENTO  OF WS-AUDIT-WORK
           MOVE 'CNTNERR01'   TO AU-COD-EVENTO   OF WS-AUDIT-WORK
           MOVE WS-CHAVE-CONTA TO AU-CHAVE-REF   OF WS-AUDIT-WORK

from datetime import datetime

logging.basicConfig(

# Mapa de dependências — simula o flow do Control-M
FLOW = {
    "EBJLOAD": {
        "predecessors": [],               # sem predecessor
        "jcl_member": "EBJLOAD",
        "condition_out": "LOAD-OK",
        "max_rc": 0
    },
    "EBJVALD": {
        "predecessors": ["LOAD-OK"],
        "jcl_member": "EBJVALD",
        "condition_out": "VALD-OK",
        "max_rc": 4
    },
    "EBJPOST": {
        "predecessors": ["VALD-OK"],
        "jcl_member": "EBJPOST",
        "condition_out": "POST-OK",
        "max_rc": 4
    },
    "EBJSALD": {
        "predecessors": ["POST-OK"],
        "jcl_member": "EBJSALD",
        "condition_out": "SALD-OK",
        "max_rc": 4
    },
    "EBJEXTR": {
        "predecessors": ["SALD-OK"],
        "jcl_member": "EBJEXTR",
        "condition_out": "EXTR-OK",
        "max_rc": 0
    },
    "EBJCONC": {
        "predecessors": ["EXTR-OK"],
        "jcl_member": "EBJCONC",
        "condition_out": "CONC-OK",
        "max_rc": 0
    },
    "EBJEOD": {
        "predecessors": ["CONC-OK"],
        "jcl_member": "EBJEOD",
        "condition_out": "EOD-OK",
        "max_rc": 0
    },
}

conditions_ativas = set()  # conditions satisfeitas
HLQ = "Z77948.EMUNAH.DEV.JCL"

def submete_e_aguarda(job_name, member):
    """Submete JCL via Zowe e aguarda completion"""
    logging.info(f"SUBMIT {job_name}")
    result = subprocess.run(
        ["zowe", "zos-jobs", "submit", "data-set", f"{HLQ}({member})"],
        capture_output=True, text=True
    )
    # Extrai jobid da saida do Zowe
    jobid = None
    for line in result.stdout.splitlines():
        if 'jobid' in line.lower() or 'JOB' in line:
            jobid = line.split()[-1].strip()
            break
    if not jobid:
        logging.error(f"Nao foi possivel obter JOBID para {job_name}")
        return 99
    # Aguarda completion
    for _ in range(30):  # max 150s
        time.sleep(5)
        st = subprocess.run(
            ["zowe", "zos-jobs", "view", "job-status-by-jobid", jobid],
            capture_output=True, text=True
        )
        if "OUTPUT" in st.stdout or "CC " in st.stdout:
            rc_line = [l for l in st.stdout.splitlines() if "CC " in l]
            rc = int(rc_line[-1].split("CC ")[-1].strip()[:4]) if rc_line else 0
            logging.info(f"{job_name} ({jobid}) RC={rc}")
            return rc
    logging.error(f"Timeout aguardando {job_name}")
    return 99

def roda_flow():
    """Executa o flow do dia simulando o Control-M"""
    logging.info("=== EMUNAH CTM-SIM — INICIO DO DIA ===")
    for job, cfg in FLOW.items():
        # Verifica predecessores
        pendentes = [p for p in cfg["predecessors"] if p not in conditions_ativas]
        if pendentes:
            logging.warning(f"[HOLD] {job} — aguardando conditions: {pendentes}")
            continue
        rc = submete_e_aguarda(job, cfg["jcl_member"])
        if rc <= cfg["max_rc"]:
            conditions_ativas.add(cfg["condition_out"])
            logging.info(f"[OK] Condition {cfg['condition_out']} adicionada")
        else:
            logging.error(f"[FAIL] {job} RC={rc} — Flow BLOQUEADO")
            break
    logging.info("=== FLOW CONCLUIDO ===")

if __name__ == "__main__":
    roda_flow()

# promote_dev_hml.ps1 — Promove elemento de DEV para HML
# Simula o PROMOTE do Endevor/ChangeMan
param(
  [Parameter(Mandatory=$true)]
  [string]$Programa,     # Ex: EBPOST01
  [string]$Tipo = "COBOL" # COBOL, JCL, COPY
)

$HLQ_DEV = "Z77948.EMUNAH.DEV"
$HLQ_HML = "Z77948.EMUNAH.HML"
$DATE    = Get-Date -Format "yyyyMMdd-HHmmss"

Write-Host "[PROMOTE] $Tipo($Programa) DEV -> HML"
Write-Host "[PROMOTE] Data: $DATE"

# 1. Verifica existencia no DEV
$check = zowe zos-files list members "$HLQ_DEV.$Tipo" 2>&1
if ($check -notmatch $Programa) {
    Write-Error "[PROMOTE] ERRO: $Programa nao encontrado em $HLQ_DEV.$Tipo"
    exit 8
}

# 2. Copia membro DEV para HML via REXX no host
$rexx = @"
/* REXX - Copia membro DEV para HML */
CALL OUTTRAP 'LINHAS.'
'ISPEXEC LMINIT DATAID(DEVIN) DATASET(''$HLQ_DEV.$Tipo'')'
'ISPEXEC LMINIT DATAID(HMLOUT) DATASET(''$HLQ_HML.$Tipo'')'
'ISPEXEC LMCOPY FROMID(DEVIN) FROMMEM($Programa) '||,
         'TODATAID(HMLOUT) TOMEM($Programa) REPLACE'
'ISPEXEC LMFREE DATAID(DEVIN)'
'ISPEXEC LMFREE DATAID(HMLOUT)'
SAY 'PROMOTE OK: $Programa DEV->HML'
Return 0
"@

$rexx | Out-File ".\rexx\temp\PROMOTE.rex" -Encoding ASCII
zowe zos-files upload file-to-data-set ".\rexx\temp\PROMOTE.rex" "Z77948.EMUNAH.DEV.REXX(PROMOTE)"

Write-Host "[PROMOTE] Registrando no change log..."
Add-Content ".\docs\change-log.md" "| $DATE | PROMOTE | $Tipo | $Programa | DEV->HML | $(git log -1 --pretty='%s') |"

Write-Host "[PROMOTE] Concluido. Lembre de recompilar em HML!"

Como ler o dump gerado (sem Fault Analyzer)

DUMP READING — Guia de diagnóstico manual
Quando o job terminar com ABEND S0C7, no spool SYSABEND:

1. Procure a linha: "COMPLETION CODE  SYSTEM=0C7"
   COMPLETION CODE  SYSTEM=0C7  USER=0000

2. Ache o PSW (Program Status Word) e o offset:
   ABEND S0C7  PSW AT ABEND 00E00000 8001AB3C
               └── 8001AB3C = endereço da instrução que falhou

3. No SYSPRINT do compilador (com MAP), localize o offset:
   Subtraia o endereço do início do programa do endereço do ABEND
   Essa diferença é o OFFSET dentro do programa compilado

4. No mapa de compilação (SYSPRINT com LIST,MAP), encontre
   qual paragrafo/instrução corresponde a esse offset

5. Regra prática: procure no dump por registros GR0-GR15
   Em S0C7, o registrador que aponta para o dado inválido
   vai estar numa área com caracteres não numéricos

# EMUNAH-001 — Bug: EBJVALD sem DD VALIDOS

**Status:** RESOLVIDO
**Tipo:** Bug
**Prioridade:** P1-Critica
**Assignee:** Desenvolvedor
**Data abertura:** 2026-03-15
**Data resolucao:** 2026-03-15

## Descricao
EBJVALD nao define o DD VALIDOS necessario para EBVALI01.
O programa tenta abrir o arquivo VALIDOS e recebe OPEN error.

## Causa Raiz
JCL criado com foco no arquivo de rejeitos mas esqueceu
o arquivo de saida de registros validos.

## Solucao Aplicada
Adicionada DD VALIDOS apontando para LANCTO.ESDS.
Corrigido tambem o DDNAME de REJEITO para REJEITOS
para bater com ASSIGN TO REJEITOS no COBOL.

## Arquivos Alterados
- jcl/batch/EBJVALD.jcl
- docs/04-mapa-datasets.md (adicionado LANCTO.ESDS como saida)

## Evidencias
- Spool do job antes da correcao: CC 0012
- Spool do job apos correcao: CC 0000
